# JeLauncher — agent guidelines

JeLauncher is a Minecraft launcher built with Rust + Tauri and a React frontend.

## Language

- Everything is written in English: code, identifiers, comments, docs, commit
  messages, PR descriptions and the English UI strings (translations live in locale files).
- Keep comments to a minimum. Prefer clear names; comment only to explain *why*,
  never *what*.

## Structure

```
crates/core/        pure Rust: all launcher logic, no Tauri dependency
crates/tauri-app/   thin Tauri layer: commands, events, tauri.conf.json
ui/                 React + TypeScript + Vite + Tailwind + shadcn/ui
  src/app/          app root and providers
  src/pages/        main/, instance/, settings/
  src/dialogs/      dialogs (NewInstance, About, Export…)
  src/components/   shared components; ui/ holds generated shadcn components
  src/hooks/        TanStack Query hooks over Tauri commands
  src/bindings.ts   generated by tauri-specta — do not edit by hand
```

`crates/core` is split by domain: `instance`, `minecraft`, `java`, `meta`,
`modplatform`, `net`, `settings`, `auth`…

## Commands

- Run in dev: `cargo tauri dev` from the repository root.
- Checks: `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo fmt --all`, `pnpm --dir ui build`, `pnpm --dir ui lint`.
- CI (`.github/workflows/ci.yml`) runs the same checks on Linux, macOS and Windows and fails
  when `ui/src/bindings.ts` is out of date.
- `ui/src/bindings.ts` is regenerated by `cargo test -p jelauncher` and by `cargo tauri dev`.
  Commit the updated file whenever commands or shared types change.
- Add shadcn components with `pnpm --dir ui exec shadcn add <name>`.
- Builds: `cargo tauri build --bundles app,dmg` (macOS);
  `cargo tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc --bundles nsis`
  (Windows, cross-compiled; needs `cargo-xwin`, `nsis` and `llvm`). Both are also in `.zed/tasks.json`.
- Releases: pushing a `v*` tag runs `.github/workflows/release.yml` and drafts a GitHub release with
  macOS, Windows and Linux bundles. Repository secrets `CURSEFORGE_API_KEY` and `MICROSOFT_CLIENT_ID`
  are baked into the build; `APPLE_*` secrets enable signing and notarization.
- Local builds read the same keys from the git-ignored `.cargo/config.toml` (`[env]` section).

## Task tracking (Plane)

- All work is tracked in the Plane project **JeLauncher** (identifier `JL`) via the Jestos Plane MCP.
- Workflow: `Backlog` → `In Progress` when you start a task → `PR Review` when the work is done
  and ready for review. Never move tasks to `Done` yourself — that happens after review.
- Pick up an existing work item before starting; if none fits, create one in `Backlog` first.
- Labels: `core`, `ui`, `auth`, `launch`, `modplatform`, `infra`.
- `Ref:` paths in work item descriptions point to the reference implementation of that feature.

## Git

- Never add co-authors to commits: no `Co-Authored-By:`, `Generated with ...` or
  any other agent/bot attribution — neither in commits nor in PRs.
- Commit locally as soon as a task is finished — one commit per task. Never push unless explicitly asked.
- Conventional Commits, short and imperative, ending with the Plane id
  (`feat: add Java detection (JL-29)`, `fix: handle missing asset index (JL-31)`).

## Clean code

- Code reads like the code around it: same style, naming and structure.
- Small functions with a single responsibility.
- No dead code, commented-out blocks, unexplained `TODO`s or debug logging.
- No duplication: extract shared logic into a module instead of copying it.
- Do not add dependencies without a real need.

## Rust

- `cargo fmt` and `cargo clippy -- -D warnings` must pass cleanly.
- No `unwrap()` / `expect()` in production code — propagate errors with `Result`
  and dedicated error types (`thiserror`).
- All launcher business logic lives in `crates/core` with no Tauri dependency;
  the Tauri layer only forwards commands and events to the frontend.
- Async runtime is `tokio`; networking is `reqwest`.

## Frontend

- The frontend only renders state and calls Tauri commands — no business logic.
- Types shared between Rust and the frontend are generated from Rust, never written by hand.
- UI text goes through i18next: `useTranslation('<namespace>')` and keys in
  `ui/src/locales/<lang>/<namespace>.json` for every language (`en`, `uk`, `ru`, `es`, `fr`, `pl`, `sr`,
  `pt-BR`, `zh`, `ja`, `en-PT`).
  `pnpm --dir ui lint` fails when a language misses keys; `tsc` fails on unknown keys.
  The native macOS menu reads its labels from `crates/tauri-app/locales/menu.<lang>.json`.
